# QA audit — 2026-08-27 (Fable 5, live prod, real data, both themes)

Method: full click-through of every route on ads.ecomwizards.agency (Alphainfuse · US)
via the operator's authenticated browser, after the wave-1 deploy. Each finding: route,
what happens, what should happen. Ranked: feature bug > broken flow > confusing UX >
polish. Fix batch: WP-47A (this file is the checklist; each fix re-verified live).

## A — Feature bugs

1. **Comparison deltas are dead product-wide.** Grid (all entity tabs): every Δ / Δ% /
   comparison column renders “—” for all rows while the header names a comparison period.
   Optimizer KPI tiles: “· — vs prior period ($0.00)” / “(0)” on every tile. One shared
   loader/mapping defect is likely (grid comparison columns + optimizer view model read
   the same comparison facts). Expected: real prior-period values and signed deltas.
   Files to start: `apps/web/app/_lib/grid-data.ts` (comparison aggregation),
   `apps/web/src/optimizer/view.ts::kpiTiles`, whatever loads the comparison window.
2. **/recommendations renders a queued run as if it ran.** With a run still `queued` the
   page shows “run white-box-v1 over ? to ?”, zero counts, and “This run stored no
   strategy snapshot…”. Expected: the queued/running state the optimizer page already
   shows (“Optimizer run queued”), and the snapshot message only for finished runs that
   truly lack one. File: `apps/web/app/recommendations/page.tsx` (+ its run picker —
   it should prefer the latest FINISHED run, and show queued state only when none).
3. **Dashboard KPI deltas mislead** (design-audit P1, confirmed live in both themes):
   “Sales $16,625 · ↓100.0% vs prior period ($167.97)” — parenthetical values look like
   last-day numbers, and the ↓100% is the unsettled attribution tail. Fix as one unit:
   verify the comparison grain, compare settled windows only, and shade the trailing
   ~14 unsettled days in every trend chart (dashboard + optimizer) with a “settling”
   note. Files: `apps/web/app/dashboard/page.tsx` KPI assembly, `apps/web/src/ui/viz.tsx`.
